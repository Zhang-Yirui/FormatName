# FormatName · 格式化命名

> 根据 Excel 花名册批量重命名文件的桌面工具。
> 用 Tauri 2 + Rust + Vue 3 实现，无需安装运行环境，双击即用。

老师收作业时最麻烦的不是批改，而是把「IMG_20240412.png」「未命名作业 (3).docx」这样的文件名一个个对回花名册。
**FormatName** 的做法是：导入一份花名册，选几个关键字（学号、姓名……），拼出想要的命名格式，再把作业文件夹交给它——
程序自动把每个文件和花名册里的人对应上，批量改名；改错了可以一键恢复，改之前还能先备份。

```
张三-201904020207-信计1902.docx      ←  改名前：IMG_20240412.png
李四-201904020218-信计1902.docx      ←  改名前：作业(2).docx
王五(1)-201904020219-信计1902.docx   ←  同一个人交了两次，自动加序号
```

---

## 功能特性

- **四步走流程**：导入表格 → 选择关键字 → 设置命名格式 → 数据分析，左侧步骤条实时显示进度，未完成的步骤不允许跳过。
- **多种表格来源**：`.xlsx` `.xlsm` `.xltx` `.xltm` `.csv` `.json` `.txt`，也可以直接把表格文本 / Markdown 表格交给后端解析；支持拖拽文件到窗口（原生拖拽能拿到完整路径）。
- **智能关键字**：程序自动判断每一列能不能当关键字——重复值太多的列（性别、班级）、看起来像序号的列、含非法字符的列都会被标记出来并给出原因；它们仍可出现在新名字里，但不参与文件匹配。
- **可视化命名构建区**：字段、分隔符、自定义文本都能拖进来排序，支持统一分隔符 / 每段单独设置，实时预览「命名格式 → 样例文件名」。
- **安全的批量改名**：使用「临时名中转」的两阶段重命名，保证**原子性**——中途失败会自动回滚，绝不会出现半个目录改了、半个没改的情况；也不会覆盖目录里与本次无关的同名文件。
- **一键恢复 / 备份**：改名前后状态持久化进 SQLite，重启程序后依然能恢复原文件名；也可以在改名时自动先备份整个目录。
- **重新扫描**：改名后目录里又有人补交了作业，点「刷新」即可增量处理新文件，已改名部分不受影响。
- **作业统计**：已交 / 没交 / 多交 / 未知四类名单，点击即可复制到剪贴板。

## 使用流程

### 1. 导入表格

拖入或选择一份花名册。**第一行为表头，第二行起为数据**，表头将作为关键字候选。
导入成功后立刻在下方的表格里预览解析结果，确认无误再进入下一步；若之前导入过，也可以点「继续使用上次的数据」。

### 2. 选择关键字

点击表头即可切换该列是否为关键字（选中的表头会变蓝）。鼠标悬停可查看某列「不能作为关键字」的原因。
关键字用来把**文件名**和**花名册里的某一行**对应起来，所以选学号、姓名这类能唯一标识一行的列最合适。

### 3. 设置命名格式

在右侧「命名构建区」里组合字段与分隔符：

- 左侧的表格字段、连接符号、自定义文本都可以**拖拽**进来，构建区内部也能拖动排序；双击可直接追加。
- 「统一分隔符」一键把所有连接符改成同一个（无 / `-` / `_` / `+` / 空格 / `.` / 自定义）；取消勾选后可每段单独设置。
- 预览区用表格第一行数据实时展示将要生成的文件名。

最后选择（或拖入、粘贴）**包含待改名文件的文件夹**，提交。

### 4. 数据分析

核对「新旧名字对照」表与右侧四类统计，确认后执行：

|      按钮      |                                           作用                                           |
|:--------------:|:----------------------------------------------------------------------------------------:|
|    **改名**    |                             按对照表批量重命名；失败自动回滚                             |
|    **恢复**    |                                 按对照表把文件名改回原样                                 |
| **备份并改名** |        先在目录下生成 `YYYY年MM月DD日 HH时MM分SS 备份` 子目录复制全部文件，再改名        |
|    **刷新**    | 重新扫描目录：未改名时整份重算；已改名时增量处理（新文件立即改名、消失的文件移出对照表） |

## 重命名是怎么做的

1. **匹配**：每个关键字的值被当成**正则**去文件名里搜索（非法正则自动退化为普通文本匹配）。
   一个文件名可能同时匹配到多个关键字，此时取「匹配到的片段最长」的那一行；长度相同则取优先级更高的关键字
   （关键字按重复次数 `delta` 升序排序，重复越少优先级越高）。
   因此序号 `1` 这种能匹配几乎所有文件名的短值，不会盖住真正的学号。
2. **生成新名字**：按命名格式依次拼接列值 / 文本，空值写成「空值」；保留原文件扩展名。
   同一行被匹配多次时，第二个起追加 `(1)`、`(2)`…… 后缀。
3. **落盘**：先校验目标名字不重复、也不与目录里无关文件重名；
   再把所有旧名字改成一个唯一的临时名（`__format_name_tmp__N`），最后统一改成目标名。
   这样即使「A 的旧名字 = B 的新名字」这种链式冲突也不会丢文件；任何一步出错都会回滚。

## 注意事项

- **不要把本程序和要改名的文件放在同一个文件夹里**——提交目录时后端会拒绝包含程序自身的路径。
- 新文件名中不能包含 Windows 非法字符 `| > < ? * " : \ /`，含这些字符的列会被禁用并标红。
- 备份与恢复都基于本次的「新旧名字对照表」，改名后请不要手动改动对照表中的文件，否则可能恢复不到原样。
- 程序数据（导入的花名册与改名任务）保存在应用数据目录的 `format_name.db`（SQLite）中，删除它即可完全重置。

## 前后端接口

前端通过 `src/api/index.ts` 调用 `src-tauri/src/command.rs` 中导出的命令：

|                   命令                    |                           说明                            |
|:-----------------------------------------:|:---------------------------------------------------------:|
|              `get_app_info`               | 程序名称 / 版本 / 描述 / 作者 / 协议（来自 `Cargo.toml`） |
| `submit_excel_path` / `submit_table_text` |                  导入表格文件或表格文本                   |
| `get_data` / `submit_data` / `clear_data` |                  读取、保存、清空列数据                   |
|                 `is_dir`                  |              判断路径是否为目录（拖拽校验）               |
|             `submit_execute`              |         提交目标目录与命名格式，生成新旧名字对照          |
|               `get_execute`               |              获取对照表、统计标记与改名状态               |
|                 `rescan`                  |                  重新扫描目录并重算对照                   |
|      `rename` / `recover` / `backup`      |                  执行改名 / 恢复 / 备份                   |

统一返回 `{ code, msg }`，`code === 0` 表示成功，其余为各类业务错误（文件不存在、表头重复、新名含非法字符等）。

## 开发说明

- 前后端数据结构一一对应：`src/types/index.ts` ↔ `src-tauri/src/model.rs`，改动请同步两边。
- Tailwind 的 `preflight` 必须在 Element Plus 样式**之前**引入（见 `src/main.ts`），否则组件样式会被重置。
- 自定义样式统一写在 `src/style.css` 的 `@layer` 内，避免盖掉同权重的工具类。
- 核心逻辑（关键字选择、批量重命名的原子性、数据库读写、各类表格解析）在 `src-tauri` 中都有单元测试覆盖，改动后请运行 `cargo test`。
